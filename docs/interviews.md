# Cinematic interviews

Conversations keep the character in view, accept microphone speech and show one subtitle turn at a time. Authored topic buttons and response choices are available alongside optional live voice conversation under Or speak in your own words. Choices appear after playback finishes; completed topics can be replayed. Recorded on the Case Map links collected discoveries to their evidence records. There is no text-entry box. Click Start talking once; the microphone then listens hands-free and sends each message when the player stops speaking. Hold to talk is the alternative, using the button or Space. The player's words appear as their subtitle while the character prepares a reply.

The scene fills the screen during an interview. The navigation, location list and footer return when it closes. The witness name and close/mute controls remain available. The microphone and optional exhibit selector sit below the character between exchanges. Recorded statements can be replayed through the same turn-by-turn presentation.

The camera frames the witness and investigator from the side. The investigator holds a pocket notebook, writes intermittently while listening, and lifts the pencil while speaking. Nearby partners see the same activity. Reduced motion keeps the notebook still. Portrait screens widen the camera view to keep both faces visible.

## Playback

Interview records persist when the cast changes between stages. Earlier witnesses stay out of the active scene, while collected testimony on the Case Map shows the exact successful exchange that produced it, with the investigator and witness named. The record keeps denials and admissions distinct; unrelated, unsuccessful and uncollected exchanges are not added to an evidence card. Successful replies remain in the saved case; each witness retains up to eighty unsuccessful attempts in addition to those replies.

`frontend/src/interviews/conversation-playback.ts` receives an injected audio port, recording resolver and cue callback. It advances on the recording’s actual `ended` event; estimated server durations never cut the local exchange short. A subtitle becomes visible on `playing`, or when the player chooses to read. Buffering keeps the current turn and disables the microphone until playback finishes. Muting an interview silences the recordings while subtitles keep advancing; changing volume preserves the current playback position. Missing recordings and Read instead show one line with Continue. Cutscenes retain manual reading when muted. Skip line explicitly advances a voiced turn. Closing cancels callbacks and audio.

`useInterviewAudio` runs this player for the active conversation. Nearby partner audio retains the shared server timeline in `SpeechPlayback`. Received speech IDs prevent ordinary state updates from restarting a completed or manually advanced exchange. The action response includes its authoritative speech sequence, so the sender can start playback without waiting for the event stream. Outcomes and evidence still come exclusively from the backend.

Development refreshes preserve the current turn and playback position. Replies arriving after an interview closes cannot start audio over another conversation.

Characters have a small, bouncy mouth flap while speaking. `App` passes the playing cue's `speakerId` into `World3D`; only that character animates, including a nearby partner. The mouth settles closed between turns, during buffering and when playback stops or switches to reading. Keep this playful puppet motion simple, visible beneath facial hair, and disabled with reduced motion.

`Interview.tsx` owns the presentation; `useInterview.ts` submits messages and replays saved replies. `voice-turns.ts` owns turn-taking against an injected speech detector; `mic-vad-detector.ts` implements it with the Silero voice activity detector from `@ricky0123/vad-web`, whose model and runtime files Vite copies to `/vad/`. Hands-free mode ends a turn after 800 ms of silence and discards false starts. Hold to talk ends a turn on release, so pauses mid-sentence are kept. The detector pauses while the character replies and resumes afterwards. Detected speech becomes a mono 16 kHz PCM16 WAV recording, sent in bounded chunks to ConversationActor over its authenticated socket. The actor verifies ownership with CaseActor, validates the recording, calls ElevenLabs Scribe v2 through fal and limits input to thirty seconds plus a small allowance; longer speech is rejected in the browser. The fal key stays on the server. Only the final transcript is sent to the character. The microphone stays open for the whole conversation and closes when it ends; cancelling discards the current speech and aborts pending transcription. The chosen mode is remembered. Provider failures such as exhausted fal credits are shown separately from a recording with no detected speech.

The character responds to the player's actual words, including greetings, small talk and follow-ups after a clue has been established. Voice input is not repeated back in a synthetic detective voice. A failed request retains a Retry message control. Reading an exhibit opens the existing document reader and returns to the conversation.

## Document handovers and voices

Authored document handovers appear under Documents received after the exchange finishes. They remain available on return and on the shared Case Map. Preserve the original/transcription preference.

Recordings are optional story-owned assets. Register their text, file and duration in `voices`; the playback system uses readable subtitles when a matching recording is unavailable. See [asset production](assets.md).

## Intelligent characters

With Jev and fal configured, each character's private `mind` holds personality, speaking manner, goals, background and gated factual knowledge. Each appearance carries its own direction while sharing an identity for memory. The performer also receives where the conversation stands with this investigator, so a witness who has been reassured or threatened sounds like it. Jev chooses whether to engage, clarify, evade or disclose particular knowledge. Gemini Flash produces a new response to the player's message through fal’s OpenRouter chat-completions endpoint. `CHARACTER_REASONING_EFFORT` defaults to `medium`, with a 32,768-token completion budget and a two-minute model timeout. `CHARACTER_MODEL` and each character’s model override retain their model selection; unqualified model names receive the `openai/` provider prefix. Dialogue, transcription and voice generation use `FAL_KEY`. Jev checks its actual wording for unsupported facts and tracks the eligible facts actually stated. Facts accumulate across replies and both detectives for the same NPC appearance; the case awards evidence when its complete account has been stated. Ordinary conversation needs no clue or uncompleted subject. The models never write extra detective dialogue.

ConversationActor runs Jev, Gemini and ElevenLabs, and checkpoints decisions, generated responses, validation and recording metadata in actor-local SQLite. There is one actor per case and stable character identity, shared by both detectives. The case authorizes each turn and commits validated testimony and evidence. Clients receive progress and accepted reply/audio references directly from the conversation socket. A recording is generated once; both nearby players hear that same recording, subject to their audio settings and other active interviews. Both clients play the same returned fal media URL directly; the game saves no generated audio files. Old exchanges remain readable if the provider removes the recording. Reloading or reconnecting resumes pending work; ending the interview cancels it. Character memory follows a stable identity between appearances, with the full accepted transcript persisted and paginated, the latest 24 exchanges supplied to the models, and accumulated relationship standing retained separately. The server enforces possession of exhibits, disclosure prerequisites, exclusive conversations and joint reports. Jev accepts a reply when its likeliest verdict is grounded; invented and uncertain verdicts are regenerated once. A reply that fails validation twice asks the player to put it another way. Other generation failures report an interruption. Dialogue provider billing and availability failures report a specific reason. Failures award nothing and never substitute scripted dialogue.

Each reply records `performance.timings`: the milliseconds spent on Jev's decision, Gemini Flash's response, Jev's review and voice generation. Retried stages accumulate. Use these to find where a slow turn spent its time.

`FAL_KEY` enables ElevenLabs Turbo v2.5 (`fal-ai/elevenlabs/tts/turbo-v2.5`) through fal. Each character response has its text and measured audio duration saved with the reply. Voice failure leaves the response readable. Existing cutscenes retain story-owned recordings.

## Checks

- `npm test` covers playback sequencing, buffering, repeated snapshots, missing or muted recordings, cancellation, leases, interview rules and stage requirements.
- With `npm run dev:framework` running, `npm run test:framework` checks a deterministic fixture exchange and its evidence reward alongside the document, object and Case Map flow.
- `node scripts/interview-sync-check.mjs` checks delayed replies and development refreshes. Set `FRAMEWORK_ORIGIN` when using a preview other than port 5288.
- With the development server running, `npm run test:microphone` checks actual browser speech detection using synthetic speech and a mocked transcription provider: silence is never uploaded, hands-free mode sends when speech ends, hold to talk ignores speech while released, and the microphone closes with the conversation. `MIC_TEST_ERROR=credits` checks billing error feedback. Set `MIC_TEST_LIVE=1` to use Scribe v2 through fal instead; this uses fal credits. Both modes exercise the browser conversation client and actor message handler through an intercepted WebSocket, without creating or changing a case. Set `AI_ORIGIN` for a preview other than port 5488 and `MIC_TEST_WAV` for a supplied recording instead of macOS speech synthesis.
- With the Sixth Murder live server running, `npm run test:ai` checks real Jev/Gemini Flash/fal requests, browser speech playback, fal microphone transcription, small talk, conversational memory, evidence disclosure, shared replies, retries and reloads, and logs each reply's stage timings. This uses provider credits.
- `npm run test:persistence` starts an isolated runtime and verifies a pending decision, performance and fal request checkpoint across two complete runtime restarts without calling the providers.

Dialogue, appearances, optional portrait images and recordings belong to the selected story package. No witness ID has special handling. `repeatable: false` makes that character's questions one-attempt; `requiredTopics` defines the successful answers needed for chapter readiness. See [story authoring](story-authoring.md).

A successful reply may set `endsInterview: true`. This ends all questioning of that character, including live replay and reopening by either player after reload. The final exchange finishes playback before the report opens; it does not submit a report or bypass joint agreement. A topic outcome of `closed` remains a refusal on that topic only. Collected statements stay readable on the Case Map.
