# Investigation mechanics

Whitechapel connects scene exploration, witness interviews and evidence on a shared Case Map. A useful interview tests a particular claim against something the investigators have found. Eye contact, nervousness, accent and appearance are not proof of guilt.

## Whitechapel framework

| Mechanic | Behavior |
| --- | --- |
| Scene inspection | Walkable scenes, evidence hotspots and authored physical inspection steps |
| Case Map | Shared evidence, fixed papers, red-thread connections and previous chapter review |
| Interview tactics | Authored Reassure / Press / Challenge choices with the intended words visible |
| Evidence challenge | The server checks discovered evidence against the claim’s authored proof |
| Outcomes | Replies can award testimony, change trust, record a choice or leave a topic unresolved |
| Recovery | Topics allow retries by default; one-attempt topics need an authored route around any essential missed finding |
| Case assessment | Evidence connections, optional sequence reconstructions and joint chapter conclusions |
| Partnership | Independent travel, shared discoveries, visible partner and exclusive witness conversations |

Trust records disposition and outcomes. Optional live conversations use character memory and validated disclosures alongside the authored branches. Inspectors have distinct names and appearances without separate skill trees. A story defines prerequisites, available approaches and consequences explicitly.

An interview must react to the evidence selected. A valid contradiction should prompt an answer to that contradiction. Required clues and conclusions must remain obtainable through the authored paths; reference validation cannot prove that every narrative branch is solvable.
